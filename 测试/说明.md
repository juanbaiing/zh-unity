# 自动化测试

这些脚本靠**调试端口驱动真 exe**，不是模拟页面，跑的是真程序。

## 怎么跑

```
1. 先起一个带调试端口的 exe：
   $env:ZH_EDITOR_DEBUG_PORT = "9223"
   .\发布\中文套式编辑器.exe

2. 另开一个终端，跑其中任意一个：
   node 测试\拖动场景1.js      拖到标题行/已有块里/自己子孙里/画布空白/分支栏/连续拖
   node 测试\拖动场景2.js      从分支拖出/进否则栏/四层嵌套/靠左/撤销
   node 测试\拖动场景3.js      新加分支后拖/删完再拖/连撤重做/原地松开
   node 测试\拖动场景4.js      拖到输入框上/空容器里再拖/Esc 中断/拖到边栏删
   node 测试\回归.js           容器块嵌套/边栏拖宽/生成/编译检查/多工程/存档/清空
   node 测试\找茬.js           怪字符/超长名/坏存档/连点新建/孤岛块/块缝
   node 测试\边界值.js         拖动阈值/负坐标/12 层嵌套/超长字段/画布边界
   node 测试\逐行对齐.js       中间层与 C# 行数、行号、行高、空行、列宽、滚动联动
```

## 中间层和 C# 为什么要逐行对齐

中间层（中文转写）和右边生成的 C# 是同一件事的两种写法，行应该一一对上，
第 N 行说的是同一件事。为此有三条硬约束，动其中任何一处都要重新跑 `逐行对齐.js`：

1. **行数一样** —— 空行两边都得留（`译脚本` 对空行的处理、`生成` 里补 `using` 的位置
   都影响行数，`新建列表` 的 `System.Collections.Generic` 必须由 `生成` 这边加，
   不能靠翻译器事后补，否则凭空多一行整体错位）
2. **行高一样** —— 两边共用 `画行()` 函数和同一套 `.codelines` 样式；
   连标题条（「中间层」和「生成的 C#」）都得同字号同行高，差 1px 就整列歪
3. **大括号不重复** —— 中文源码里 `{` `}` 各占一行，翻译器看到就直接照搬，
   不能再用「深:1」补一个

每个脚本自己会 `Emulation.setDeviceMetricsOverride` 把视口撑到 1500×950
（真窗口只有 787×478，够不着托盘下半截），跑完会还原。

## 判据

输出里每行 `✓` 或 `✗`，`✗` 后面跟具体数据和期望。**全绿才算过**。

## 真实鼠标那条（`真实鼠标复现.ps1`）

用 Win32 的 `SetCursorPos` + `mouse_event` 操作真鼠标，会先
`SetForegroundWindow` 把 exe 请到前台，跑完把鼠标放回原位。

**局限**：本机 175% 缩放 + 窗口偏小，托盘里的块会滚出视口，
所以真实鼠标这一路点不到。要用得先把窗口拉大。

## 为什么不用纯 JS 模拟点击

页面里派发 `PointerEvent` 绕过了浏览器的输入处理，有些问题（比如 pointer capture、
elementFromPoint 的时序）复现不出来。这里的脚本走 CDP 的 `Input.dispatchMouseEvent`，
和真鼠标走同一条输入管道。
